# Phase 6 — Invitation, RSVP and sharing

Base: `v2/p05-theme-engine` · Branch: `v2/p06-invitation`

Before the wedding, `shubhobiye.com/{slug}` is now a real invitation: both families, the events with maps and calendar buttons, a countdown, an RSVP form and a share card. On the wedding days the same link shows what is happening today and the livestream. After the wedding, once the couple publishes, it becomes the full memories site. Everything uses the site's theme, so Cinematic and Jharokha invitations look as different as their sites do.

## Migration to run
`supabase/migrations/20261023000001_rsvp.sql` — adds the `rsvps` table (RLS on, no anon or authenticated access). Paste it into the Supabase SQL editor before or when merging.

## What changed

**Routes**
- `/{slug}` follows the phase: **invitation** → **live** → **memories** (`lib/phase.js`).
- `/{slug}/invite` always shows the invitation, and `/{slug}/memories` always shows the full site. Guests are sent back to `/{slug}` until memories are published; the couple and operators can always open it.
- `/{slug}/calendar.ics` exports every event (or one, with `?event=`) in UTC, with lines folded per RFC 5545.
- `/{slug}/og.jpg` is the link-preview card, drawn with canvas so Bangla shapes correctly. Chat apps fetch it without the guest's cookie, so:
  - the names always show;
  - the date shows only when the invitation is public;
  - the cover photo shows only when the couple turns that on and the photo is public.

  The URL changes whenever the content or settings change, so previews refresh.
- The preview bar has **Invitation / Full site** switches for the couple and operators.

**Invitation** (`src/site/invite/*`, theme variant `invite`: `classic` or `arch`)
- **Order:** opening → hero (cover photo) → invitation card → families → countdown → events → RSVP → photos → share → closing → footer.
- **Invitation card:** the tradition's wording (overridable), the names, the date, and the date in the tradition's calendar:
  - Hijri for Muslim weddings;
  - the Bangla calendar for Hindu and Buddhist weddings, using the Bangladesh 2019 revision, e.g. ২৭ অগ্রহায়ণ ১৪৩৩ বঙ্গাব্দ.

  It also shows the verse.
- **Families:** "Daughter of … / Son of …" in English. In Bangla it reads naturally, as "…-এর কন্যা".
- **Countdown:** counts to the main ceremony by default (the couple can pick another event). It renders on the client only.
- **Events:**
  - Cinematic uses a dated timeline; Jharokha uses arched cards with the event photo.
  - Each event has map, calendar file, Google Calendar and "Watch live" buttons.
- **Live view:** a "Happening today" band and the guestbook.
- **Share:** WhatsApp text, copy link, the calendar file, and a QR code (desktop only) to open the invitation on a phone.
- **New copy:** all invitation text is in `src/traditions/copy.js` (English and Bangla). Each tradition has its own wording and closing (Muslim, Hindu, Christian, Buddhist; Universal uses the default).

**RSVP**
- `POST /api/g/:slug/rsvp`:
  - checks same-origin, honeypot and rate limits (10 per 10 minutes per device, 400 per hour per site);
  - validates the input with zod;
  - only accepts events that take RSVPs, enforces the party-size limit, and requires a phone number when the couple asks for it.
- **Deadline:** the reply-by date includes that whole day in Dhaka. Without a date, replies close when the last event starts.
- **Changing a reply:** a signed cookie (`shb_r_<site>`, 180 days) lets the same phone update its own reply instead of creating a second one. `GET` prefills the form.
- **Couple side:**
  - `GET /api/sites/:id/rsvps` lists replies, and `?format=csv` exports them for Excel (UTF-8 with BOM, so Bangla shows correctly, with spreadsheet-formula protection);
  - `DELETE /api/sites/:id/rsvps/:rsvpId` removes a reply.

**Editor**
- **Invitation** panel:
  - wording;
  - verse on/off;
  - both families;
  - cover and up to 10 photos (saving marks them public, so a public invitation can show them);
  - cover photo on the link preview;
  - countdown event;
  - RSVP settings (on/off, reply-by date, most guests per reply, phone);
  - closing and signed-by.
- **RSVPs** panel: totals, guests per event, the list, delete, and CSV download. It refreshes every time it is opened.
- **Ceremonies:** venue address, livestream link (YouTube or Facebook only), "Show on the invitation" and "Guests can RSVP". Map links are now limited to Google Maps or Apple Maps.

**Other fixes**
- Sign-in reports Supabase's own rate limit as "Too many sign-ins" (429) instead of "Incorrect email or password", and doesn't count it as a failed attempt.
- `Button` with `href` renders a plain link for downloads and API routes.
- Shared renderer helpers live in `src/site/compose.js`. `SitePage` now holds the page logic for all three routes.

## How to test
1. Paste the migration, then run `npm run dev -- -p 3210`.
2. `node scripts/seed_preview.mjs <photosDir>` creates `theme-review` with an invitation, both families and RSVPs on.
3. Open `/theme-review` as a guest (private window):
   - the invitation, with the wedding date and its Hijri line;
   - a countdown to the wedding;
   - events with maps and calendar buttons;
   - the RSVP form.
4. Reply, reload and change the reply. In the editor, **RSVPs** shows one reply; download the CSV and open it in Excel.
5. As operator, add `?theme=jharokha` for the arched layout. Use the preview bar's **Full site** to see the memories view.
6. **Live view:**
   - in Site settings, set the phase override to **live**;
   - set one ceremony's start to today;
   - check that the "Happening today" band and the guestbook appear.
