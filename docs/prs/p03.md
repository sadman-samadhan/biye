# Phase 3 — Private media pipeline & photo protection

Base: `v2/p02-editor-ui` · Branch: `v2/p03-media`

Every photo and video now lives in a **private** bucket. Content stores `media:<id>` tokens instead of URLs; guests only ever receive short-lived signed URLs for resized copies.

## What changed

**Storage adapter (`lib/server/storage/`)** — one interface (`createUploadTarget`, `head`, `get`, `put`, `remove`, `removePrefix`, `signGet`) with two drivers:
- `supabase` (default): private bucket `site-media-private`, signed upload/download URLs, signed URLs reused for most of their life so browsers can cache photos between visits.
- `r2`: Cloudflare R2 via `aws4fetch`; signing time floored to the hour so URLs are identical (cacheable) within an hour. Turn on with `STORAGE_DRIVER=r2` + `R2_*` vars — no code change.
- Layout: everything for a site under `sites/{siteId}/…` (purge = one prefix delete), uploads land in `tmp/{siteId}/…`.

**Upload flow (bypasses Vercel's 4.5 MB body limit)**
1. Browser shrinks photos (`lib/client/prepareImage.js`: EXIF rotation, long edge ≤ 2560 px, JPEG) — 8–25 MB camera files become 1–3 MB.
2. `POST /api/sites/:id/uploads` checks plan limits (`lib/plans.js`: photos, videos, storage), rate limit, MIME, size → returns a signed direct-to-storage PUT.
3. Browser PUTs to storage; `POST /api/sites/:id/uploads/:mediaId/complete` builds **thumb 480 / web 1600 (optionally watermarked) / master 2048** + a blurred placeholder with sharp (`.rotate()`, metadata/GPS stripped), enforces the quota atomically (`add_storage_usage` RPC), marks the `media` row ready. Videos are size-checked in place.
- Members and operators can use it (couples get it in Phase 7's dashboard).

**Media APIs** — `GET /media` (library + usage), `PATCH|DELETE /media/:id`, `GET /media/:id/download` (couple/operator only: 5-minute signed link to the master with a filename), `POST /media/rebuild` (re-render guest copies from masters after toggling the watermark), `POST /palette` (AI colours from one of the site's own photos, 10/day), `POST /monogram` (stored as site media, 20/day). The old `/api/upload`, `/api/palette` and `/api/monogram` are removed.

**Rendering** — `resolveContentMedia()` swaps tokens for signed URLs at render time (gallery items also get thumb/size/placeholder); unknown or non-public media resolve to empty, so nothing private leaks. Next's image optimizer is off (variants are pre-built and URLs are private).

**Automatic clean-up** — after each content save, media no longer referenced anywhere (and older than 6 hours, so unsaved edits survive) is deleted with its files and the quota is credited back. Site purge deletes `sites/{id}/`, `tmp/{id}/` and any legacy public-bucket files.

**Photo protection on wedding sites** (`MediaGuard` + CSS on `[data-protected]`):

| Layer | Stops |
|---|---|
| Private bucket + signed URLs (2 h) | Strangers, enumeration, hotlinking, search indexing |
| Guests get ≤ 1600 px copies, metadata/GPS stripped; masters only via the couple's download link | Print-quality leaks, location leaks |
| Optional baked watermark (`shubhobiye.com/<site>`), rebuildable | Anonymous reposting |
| No right-click / long-press save menu, no drag-out, `-webkit-touch-callout:none`, hidden when printing | Casual saving, incl. WhatsApp/Facebook in-app browsers |
| Blur while the tab is hidden | App-switcher thumbnails |
| (Phase 4) viewer-name overlay in the lightbox, passcode gate | Casual screenshots; uninvited visitors |

Screenshots and phone cameras can't be blocked by any website.

**Editor** — uploads go through the new flow; previews resolve tokens via a media-URL context; the carousel picker accepts a `resolveSrc`. AI palette and monogram are available to couples too.

**Legacy migration** — `scripts/migrate_media.mjs` (dry run by default, `--apply`, `--site=slug`) moves files from the old public `site-media` bucket into the private pipeline and rewrites content to tokens. Idempotent.

## Environment (optional)
`STORAGE_DRIVER=r2`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` — leave unset to stay on the private Supabase bucket. For R2, create a private bucket with a CORS rule allowing `PUT` from your site origin(s).

## Verified locally
- Playwright editor e2e passes with real uploads through the new pipeline.
- Storage: 3 variants per photo, quota counter matches, no temp files left; content holds only tokens.
- Guest page: only signed `web`/`thumb` URLs, no tokens, no masters; public path to a private object → 400; tampered token → 400; couple download → 302 signed master; anonymous download → 401.
- Quota exceeded → 413; SVG upload → 415; video upload + complete works; removing a gallery photo and saving deletes its row + files and credits the quota.
- Migration script: dry run → apply → re-run is a no-op.
- `npm test` 18/18 (token parsing/mapping, schema, R2 presign determinism within an hour, plan limits); `npm run smoke:security` **59/59 refused** (new: private-bucket list/read/upload, upload/media/download/palette/monogram APIs).
- Gemini colour matching falls back to curated palettes when the model doesn't answer (the key in `.env.local` didn't return a palette locally).
