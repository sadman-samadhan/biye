# Phase 1 — Auth, data layer & ShubhoBiye rename

Base: `v2/p00-containment` · Branch: `v2/p01-auth-rename`

Real accounts for operators and couples, a server-only data layer with per-site authorization, and the new brand.

## What changed

**Accounts (Supabase Auth + `@supabase/ssr`)**
- One sign-in page for everyone: `/login` → `POST /auth/login` (rate-limited per IP and per email, same-origin only, safe `next` redirects). Operators land on `/admin`, couples on `/dashboard`.
- Operators are users with `app_metadata.role = 'admin'` (only the service role can set it): `npm run admin:make -- you@example.com 'long-password'`.
- Couples are invited by an operator: `POST /api/admin/sites/:id/members {email, role}` returns a one-time link (`/auth/confirm?token_hash=…&type=invite&next=/dashboard/set-password`) to send on WhatsApp. Existing accounts get a sign-in link instead. `GET`/`DELETE` list and remove members.
- `/auth/confirm` (invite / magic-link / recovery), `/auth/password` (set password), `/auth/signout`.
- `src/proxy.js` now refreshes the Supabase session and redirects `/admin` and `/dashboard` for UX; every page and handler re-checks on the server (`lib/server/auth.js`). The Phase 0 stopgap cookie and `/admin/login` are gone (`/admin/login` → 308 `/login`).

**Authorization (`lib/server/auth.js`)**
- `requireAdmin()`, `authorizeSite(siteId, roles)` (admins always pass; members by `site_members` role; non-members get **404** so ids can't be probed), `assertSameOrigin()` on every state-changing route, page guards `requireUserPage` / `requireAdminPage`.

**Server-only data layer**
- `lib/server/supabase.js` (service client fails closed, no anon fallback; SSR client), `lib/server/site-data.js` (cached site/content/access lookups, effective expiry, audit log writer), `lib/server/site-view.js` (`getSiteForRequest`: live sites are public; drafts/trash/expired visible to the couple and operators with a banner).
- `lib/getData.js` and `lib/supabase.js` deleted. Client components import only `lib/media.js` (pure path helpers); demo data lives in `lib/demo.js` and never reaches the client bundle as a fallback.
- `lib/server/rate-limit.js` uses the new Postgres `rl_hit` / `rl_blocked` RPCs (works across serverless instances), with IPs HMAC-hashed.

**Site APIs for couples and operators (`/api/sites/[siteId]/…`)**
- `GET` editor payload (operator CRM fields hidden from couples).
- `PATCH /content {section, data, expectedVersion}`: zod-validated per section (`lib/content/schema.js`), deep safety check (script URLs, oversized text, prototype keys), compare-and-swap on `site_content.version` → **409** for stale editors.
- `PATCH /settings`: couples may change palette/theme/tradition/contact/memories; slug, status, plan, products, expiry and owner fields are operator-only. Palettes must be hex.
- `PATCH|DELETE /messages/:messageId` scoped to the site (fixes cross-site message IDOR).
- Operator APIs (`/api/admin/sites`, `/:id`) validate every section and setting the same way; slugs go through `lib/slugs.js` (format + reserved words, since slugs become root URLs in Phase 4). Permanent delete requires the site to be in Trash first and aborts if media can't be purged; purge now paginates.
- Guestbook honours the site's moderation setting.

**Migration `20261021000001_accounts_access.sql`**
- `site_members`, `site_access` (invite/site access mode, encrypted passcode + version, moderation, watermark), product/phase/theme columns on `sites`, `site_content.invitation` + `version`, `audit_log`, `rate_limits` + `rl_hit()` / `rl_blocked()` (service-role only). Every new table: RLS on, no policies, anon/authenticated revoked.

**Brand: ShubhoBiye (শুভ বিয়ে)**
- Marigold logo (chosen concept B) in `public/brand/shubhobiye/` (lockup light/dark, mark, `og.jpg` share card), `src/app/icon.svg`, `apple-icon.png`, `favicon.ico`. Wordmarks are vector outlines, so they render without fonts.
- `<BrandLogo>` and `<DeveloperCredit>` (“Developed by 🐵 BigApeWeb.com”, icons copied from the BAW project) in the marketing footer, every wedding-site footer (beside “Made with ShubhoBiye”), the admin console and the couple dashboard.
- All “AmarBiye” copy renamed; `package.json` name `shubhobiye`. The Bismillah page loader now only mounts on wedding sites.

**New pages**: `/login`, `/dashboard` (your sites), `/dashboard/set-password`; admin layout is now a server guard around a client shell.
