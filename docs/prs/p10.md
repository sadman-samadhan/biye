# Phase 10 — Launch hardening

Base: `v2/p09-marketing` · Branch: `v2/p10-hardening`

The last phase: migrating old content, daily housekeeping, the privacy notice and terms, photo consent at intake, and up-to-date project docs.

## What changed
- **`scripts/migrate_content.mjs`** brings sites created before v2 up to date. It is a dry run by default (`--apply` makes the changes, `--site=<slug>` limits it to one site) and safe to re-run. It:
  - maps the `classic` theme to `cinematic` and the `general` tradition to `universal`;
  - defaults missing products to `['site']`;
  - converts ceremony `flow` to `beats` and gives every ceremony an id;
  - creates a guest passcode where a site has none;
  - reports addresses that break the slug rules (renaming them is manual).

  Run it with `node --conditions=react-server --env-file=.env.local scripts/migrate_content.mjs`. Then run `scripts/migrate_media.mjs` for photos still in the old public bucket.
- **Passcode encryption** moved to `lib/server/passcode-crypto.js`, so the script can use it. `guest-access.js` re-exports it; behaviour is unchanged.
- **`/api/cron/daily`** (run by Vercel Cron via `vercel.json` at 03:00 Dhaka, authorised by `CRON_SECRET`):
  - removes rate-limit counters older than a day;
  - removes uploads that never finished (pending for over a day) with their stored files;
  - its queries keep a free Supabase project from pausing.
- **`/privacy` and `/terms`** are plain-language pages. Every claim was checked against the code (what is stored, cookies, Gemini use, deletion cascades, protection limits). Both are linked from the marketing footer, the intake form and the couple's set-password page.
- **Consent at intake:** operators must confirm that the couple accepted the terms and may share their photos. The create API refuses a site without `consent: true` and records it in the audit log.
- **Docs:** `PROJECT_CONTEXT.md` rewritten for v2. `README.md` is now real setup, checks and deploy steps (the old one was the UTF-16 create-next-app boilerplate). `.env.example` documents `CRON_SECRET`.

## Before launch (you)
- **Vercel:** set `CRON_SECRET` (16+ characters), the guest secrets, `IP_HASH_SALT` and `NEXT_PUBLIC_SITE_URL`. Move to Vercel Pro before taking payments.
- **Legal:** have someone qualified read `/privacy` and `/terms`. The terms promise a reminder before a site expires; that is a manual WhatsApp step for now.
- **Old sites:** run the content migration (dry run first), then the media migration.

- **Content migration:** a dry run found 19 of 26 local sites needing changes. `--apply` updated them, and a second dry run reported 0.
- **Cron:** without the secret, 401; with it, 200 and `{"rateLimitsRemoved":6,"stuckUploadsRemoved":0,"sites":26}`.
- **Pages:** `/privacy` and `/terms` return 200.
- **Consent:** the intake button is disabled until consent is ticked (in the editor e2e). The API requires `consent: true`; seeds and tests updated.
- **Playwright:** 4/4 (editor, invitation, couple, marketing) against a production build. The editor spec needed a second run because the local Supabase timed out under load during the full run.
- `npm run smoke:security` **87/87 refused** (new: the cron endpoint with no secret or a wrong one).
- `npm test` 40/40 · `npm run lint`: 0 errors · `npm run build` passes.
