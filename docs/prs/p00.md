# Phase 0 — Containment & hygiene

Base: `main` · Branch: `v2/p00-containment`

Closes the critical holes found in the audit before any new feature work. **Merge this one first even if the rest of the stack is still in review.**

## What changed

**Private data out of the repo**
- `main` was rewritten (single root commit amended) and force-pushed so `public/images/**`, `public/videos/**`, `public/wedding-logo.png`, `data/images.json`, `data/images_temp.json` are gone from history. They are now git-ignored; local copies were left on disk.
- Demo gallery now reads an empty `data/demo-gallery.json` until the licensed demo packs land (Phase 9).
- Landing showcase, root OG image and the monogram fallback no longer reference the removed real-couple files.

**Admin authentication (stopgap until Supabase Auth in Phase 1)**
- `lib/server/admin-token.js`: HS256 JWT signed with `ADMIN_SESSION_SECRET` (12 h). Fails closed when the secret is missing/short or `ADMIN_PASSWORD` is unset. The `admin123` default is gone.
- `lib/server/admin-session.js`: timing-safe password check, `requireAdmin()` route guard, session cookie `shb_admin` (httpOnly, sameSite=lax, secure in prod).
- `/api/admin/auth`: 5 failed attempts per IP per 15 min → 429.
- `src/proxy.js` (Next 16's middleware): redirects `/admin/*` to login and returns 401 for `/api/admin/*`, `/api/upload`, `/api/monogram`, `/api/palette`. **Every one of those handlers also calls `requireAdmin()` itself.**

**API hardening**
- `/api/palette`: removed the local-file read (`imageUrl: "/../.env.local"` could exfiltrate secrets to Gemini) and arbitrary URL fetches; only this project's own storage URLs or base64 JPEG/PNG/WebP ≤ 8 MB are accepted. Upstream errors are no longer echoed.
- `/api/upload`: `siteId`/`category` restricted to safe path segments, MIME allow-list (JPEG/PNG/WebP, MP4/WebM), 25 MB image cap, extension derived from MIME.
- `/api/monogram`: input lengths clamped.

**Stored XSS**
- `normalizePalette` now accepts only `#rgb`/`#rrggbb`; anything else falls back to the default, so nothing but hex can reach the injected `<style>`.

**Guestbook**
- New `GET/POST /api/g/[slug]/messages`. The browser no longer talks to Supabase or chooses `approved`. Honeypot field + 5 posts / 10 min per IP per site. Demo sites never store or show tenant messages (fixes the cross-tenant leak).

**Public site**
- `?preview=true` removed. Drafts/trashed sites render only for a signed-in operator (with a banner); guests get 404.
- Footer no longer prints the owner's email/phone, and the fake `info@amarbiye.com` / `01700-000000` fallbacks are gone.
- Tenant pages are `noindex, nofollow, noimageindex` (metadata + `X-Robots-Tag`) and no longer publish a photo as the share image.
- Real sites never fall back to demo content when their content row is missing.

**Platform**
- Security headers on all routes (`nosniff`, `Referrer-Policy`, `X-Frame-Options: SAMEORIGIN`, `Permissions-Policy`).
- `getSupabaseAdmin()` no longer silently falls back to the anon key.
- Migrations are tracked in git (`*.sql` un-ignored), renamed to Supabase CLI timestamps, and a local stack is configured (`supabase/config.toml`, `npm run db:start`).
- `"type": "module"` in `package.json`; `npm test` (node:test) and `npm run smoke:security`.

## Database — run in the Supabase SQL editor

On a **fresh project**, run in order:
1. `supabase/migrations/20260915000001_init.sql`
2. `supabase/migrations/20260915000002_tradition_and_bangla.sql`
3. `supabase/migrations/20261020000001_lockdown.sql`

(The Supabase project referenced in `.env.local` no longer resolves, so these are the baseline for a new project.)

## New environment variables

| Name | Notes |
|---|---|
| `ADMIN_SESSION_SECRET` | 32+ random chars. Admin login is disabled without it. |

Also rotate `SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_API_KEY` and `ADMIN_PASSWORD` if any deployment of the old code was public.

## How to test

```bash
npm test                      # unit: palette hex validation, admin token forge/expiry/fail-closed
npm run db:start              # local Supabase (Docker)
npm run dev
npm run smoke:security        # every anon DB/storage probe and unauthenticated admin call must be refused
```

Manual:
- `/admin` → redirected to `/admin/login?next=/admin`; wrong password 5× → 429; right password → back to `/admin`.
- Set a site to draft → `/s/<slug>` is 404 in a private window, visible with banner when logged in.
- Post a guestbook message on `/s/demo` → accepted, not stored; on a real site → stored and listed.

## Known follow-ups (later phases)
- Admin auth moves to Supabase Auth roles (Phase 1); the stopgap cookie is deleted then.
- In-memory rate limiting becomes the Postgres `rl_hit()` limiter (Phase 1/4).
- Media goes private with signed URLs (Phase 3); the public `site-media` bucket is retired then.
- 30 pre-existing lint errors live in files rewritten by Phases 2, 5 and 9; this phase adds none.
