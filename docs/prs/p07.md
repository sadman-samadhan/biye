# Phase 7 — Couple dashboard

Base: `v2/p06-invitation` · Branch: `v2/p07-dashboard`

Couples now sign in and manage their own site: content, photos, invitation, RSVPs, privacy and sharing. They use the same editor as the operator console, without the operator-only parts.

## What changed
- **`/dashboard/[siteId]`:** the shared `SiteEditor` in couple mode.
  - Only members of that site (and operators) can open it; anyone else gets 404.
  - The Site settings and Couple access panels are hidden, and the settings API refuses operator-only fields from couples (400), as before.
- **`/dashboard`:** a couple with one site goes straight to its editor. Couples with several sites (and operators) see the list, now with an **Edit** button.
- **"Your photos"** panel:
  - a storage meter (photos used / plan limit, MB used / quota);
  - every upload with a full-size download (5-minute signed link);
  - **Download all**, which zips the full-size files in the browser (fflate, no server memory or Vercel response limits) in parts of 40 so phones cope.

  It is backed by `POST /api/sites/:id/media/download-links` (members only, same-origin, 30 requests per 10 minutes).
- **Privacy & sharing:** **Show the full site after the wedding** lets the couple publish the memories site themselves (`memories_published`). Until then the link stays on the invitation and live view.
- The editor passes `active` to panels; the RSVPs and Your photos panels refresh each time they are opened.
- Dashboard pages are wider (`max-w-6xl`) to fit the editor.

## Database
No new migration.

## How to test
1. As operator, open a site → **Couple access** → create an invite link for an email address.
2. Open the link in a private window → set a password. You land in that site's editor.
3. Upload a gallery photo → **Your photos** shows it with the storage meter → **Download all** saves `<slug>-photos.zip`.
4. **Privacy & sharing** → turn on **Show the full site after the wedding**.
5. Change the URL to another site's id: 404.
